# ESKH 02 · 系统设计

## 1. 架构总览

```
┌───────────────────────────────────────────────────────────────────────┐
│ ① 视图层  Vue 3 单页应用（hash 路由，11 个页面，零 UI 组件库）        │
│           首页 / Skill 库 / 详情 / 贡献者 / 贡献者详情 / 在线贡献 /    │
│           安全评估 / 在线文档 / 关于 / 404                             │
└──────────────────────────────┬────────────────────────────────────────┘
                               │ HTTP JSON  /api/v1/**（响应信封 code/msg/data/trace_id）
┌──────────────────────────────▼────────────────────────────────────────┐
│ ② 动作层  action/v1：SiteAction（health/meta/categories/stats/search）│
│           SkillAction（列表/详情/版本/评估/安装/下载/编辑/归档）        │
│           ContributorAction / ContributionAction / RiskAction / DocAction│
│           只做：参数校验 → 调用 → 包装                                  │
└──────────────────────────────┬────────────────────────────────────────┘
                               │ 构造器注入
┌──────────────────────────────▼────────────────────────────────────────┐
│ ③ 业务层  business：SkillService / ContributionService / RiskService / │
│           CatalogService / ContributorService / StatService /          │
│           OpLogService / LibraryImportService / DocSeedService          │
│           @Transactional 只出现在这一层                                 │
└──────────────────────────────┬────────────────────────────────────────┘
                               │ 依赖接口（不给实现）
┌──────────────────────────────▼────────────────────────────────────────┐
│ ④ 服务接口层 port：LibraryPort（读 skills/）· PackagePort（ZIP）·      │
│                    ClockPort · IdPort                                   │
│           适配器 adapter：FileLibraryAdapter / ZipPackageAdapter /      │
│                            SystemClockAdapter / ShortIdAdapter           │
└──────────────────────────────┬────────────────────────────────────────┘
                               │ MyBatis Mapper（注解 SQL）
┌──────────────────────────────▼────────────────────────────────────────┐
│ ⑤ 数据持久层  mapper：Skill/SkillFile/SkillVersion/Risk/Contributor/    │
│              Contribution/Category/Doc/OpLog/AppMeta                    │
│               H2 2.2.x（默认） · MySQL 8（profile=mysql）               │
└───────────────────────────────────────────────────────────────────────┘
```

**依赖矩阵**（review 必查）：`action → business → port ← adapter → mapper`。
动作层不碰 adapter；业务层不碰 HttpServletRequest/ResponseEntity；`@Transactional` 只在 business。

## 3. 关键时序

### 3.1 列表查询

```
浏览器 /skills?category=development&risk_level=safe&sort=download_count:desc
  → SkillAction.list（11 个显式 @RequestParam，避免下划线→驼峰绑定失效）
  → SkillService.page(query)
      · countCards(query)   —— 同一套 <where>，保证 total 与 items 一致
      · listCards(query)    —— 只查卡片列，不带 content（单条最大 40 KB）
  → CardFactory.cards()     —— 补中文标签（分类/场景/风险/身份）
  → PageResult{page,size,total,total_pages,items}
```

### 3.2 详情（一次请求拿全）

```
GET /api/v1/skills/by-id?id=lib:pdf
  → SkillService.detail(id)
      · findDetailBySkillId（含 content，一次）
      · fileMapper.findBySkillId
      · riskMapper.findLatestMeta + findSignals → RiskService.toAudit
      · installMethods(skill)  —— 3 种方式，命令里已做好 URL 编码
      · versions(skillId)
      · related(skill)         —— 同分类下载最多 6 个
```

### 3.3 编辑（一个事务里 4 件事）

```
PUT /api/v1/skills/{id}（需 X-SKH-Role: editor）
  → SkillAction.edit → SkillService.edit(@Transactional)
      1. 校验身份（viewer → 403 ROLE_FORBIDDEN）
      2. updateSelective：只改非 null 字段
      3. 若 version 或 content 变化 → 追加 skill_version（重复版本号 → 409）
      4. 若正文变化 → RiskScanner 重扫 → 写 risk_audit + risk_signal → 回填 skill.risk_*
      5. 写 op_log
```

### 3.4 发布（贡献第 4 步，一个事务）

```
POST /api/v1/contributions/{id}/publish
  → ContributionService.publish(@Transactional)
      校验：CLA 已签（否则 1300）· 未被驳回（否则 1300）
      读回上传的 SKILL.md（data/uploads/<id>/SKILL.md）
      算 skill_id：existing > 源码直链(host:owner/repo/name) > local:<contributor>/<name>
      若 Skill 已存在且该版本已存在 → 409 VERSION_EXISTS（绝不覆盖）
      新建：insert skill + skill_file + skill_version
      已有：updateSelective + insert skill_version
      扫描 → writeAudit（risk_audit + risk_signal）
      contributorService.upsert
      contribution.status = published + 回填 skill_id/risk_*
      refreshCategoryCounts（15 个分类重算）
```

### 3.5 启动自举

```
StartupInitializer.run()
  1. DatabaseBootstrap.bootstrap()     判定方言 → 执行 db/schema.sql（幂等）→ 记 schema_version
  2. LibraryImportService.importIfEmpty(false)
       skill 表非空 → 跳过（重复启动不会重复导入）
       空 → seedCategories(15) → 逐条导入 375 个 Skill：
              read SKILL.md → RiskScanner → insert skill/file/version/audit/signals → 登记贡献者
            → refreshCategoryCounts → 写 app_meta（library_version / imported_at）
       实测耗时 ~10 s（2523 个文件 sha256 + 375 次扫描）
  3. DocSeedService.seed()             读 classpath:docs/manifest.json + *.md → upsert doc_page
```

## 4. 关键设计决策（含取舍理由）

| 决策 | 理由 | 代价 |
| --- | --- | --- |
| **Skill 库放文件系统**（`./skills`）而不是打进 jar | 库有 57 MB / 2523 文件；三系统共用一份，放磁盘才能用 `sync --check` 做指纹比对 | 启动时依赖工作目录正确（`FileLibraryAdapter` 做了 `./skills` → `../skills` 回落） |
| **Java 导入器**而不是 `data.sql` | SKILL.md 里有引号/反斜杠/分号，写进 SQL 字面量极易被切坏；且导入要同时做扫描与摘要 | 首次启动多 ~10 s |
| **一份可移植 DDL** 而不是两份 | H2 与 MySQL 各一份 DDL 必然悄悄分叉 | 只能用方言子集（禁 `ENGINE=`/前缀索引/`ON DUPLICATE KEY`），已实测两端通过 |
| **业务层不套接口** | 每个服务只有一个实现，`XxxService` + `Impl` + 接口 = 三份 1:1 空壳 | 若将来真要多实现，需要改一次 |
| **前端不用 UI 组件库** | Element Plus 让包体到 1.4 MB、风格难统一 | 自研 10 个组件（约 900 行） |
| **前端不用 Vite** | 真实测试机 Node 11.16 装不上 Vite 6；本机 esbuild 被沙箱拒绝 | 自己写 60 行 Rollup 插件（别名 + CSS 抽取） |
| **`skill_id` 走 `?id=`** | 形如 `github:owner/repo/name` 含 `/`，容器会拒绝 `%2F` | 详情类端点都提供两套路径 |
| **列表参数逐个 `@RequestParam`** | 契约是 snake_case，Spring 默认不做下划线→驼峰绑定 | 11 个参数显式写一遍 |
| **风险评分用规则引擎** | 离线可跑、确定性、可解释（同一文本永远同一结果） | 语义级漏检无法覆盖 |
| **软删而非物理删** | 误删可恢复，且历史版本仍指向原 skill_id | 表会累积归档行 |

## 5. 可测试性设计

- `ClockPort` 代替 `LocalDateTime.now()`；`IdPort` 代替 `UUID` → 时间与标识可注入
- 外部依赖全部在 `port` 后面 → 单测不需要网络、不需要数据库
- `support/` 全是纯函数 → 可直接单测（`RiskScanner` / `SkillMdParser` / `Texts` / `Markdown`）
- 前端 `test/smoke.mjs` 用 jsdom 真渲染 → 不需要浏览器进程也能验证页面
