# ESKH 01 · 需求与定位

## 1. 一句话定位

**一个和 openEuler SkillHub 同构的 Skill 资源站。** 五件事在页面上闭环：浏览、编辑、贡献、分发、静态风险评估。
它**不发起任何外部网络调用**，因此在一台完全断网的机器上也能全功能运行。

## 2. 为什么先做这个版本

Skill 这件事的成熟度差异很大。对一家几十人的中小型信息企业来说，真实痛点不是
"我要做实验、要算 p 值"，而是：

> 我们有几十份 Prompt 与操作流程，散在飞书、企业微信、个人笔记里。没人知道有哪些、
> 哪些过期了、谁能改、怎么装到自己机器上。

这类组织需要的是**资源站**：能查、能看、能下载、能贡献、能看着风险分决定敢不敢用。
不需要库语义（索引/约束/触发器），也不需要在线实测。

EasySkillHub 就是这个最小可用形态，同时它也是另两个版本的**风格与质量基线**：
后两个版本必须沿用同一套界面、同一套接口、同一套错误话术。

## 3. 干系人与诉求

| 角色 | 在意什么 | 本版本怎么满足 |
| --- | --- | --- |
| **查找者**（工程师 / 产品 / 运营） | 快速找到"能解决我这个问题"的 Skill | 15 分类格子 + 6 条件筛选 + 关键词加权检索 + 2 行截断的卡片 |
| **评估者**（技术负责人 / 安全） | 这玩意安全吗？会不会偷我数据？ | 0-100 风险分 + 四档等级 + 32 条指标明细 + 每条信号的修复建议 |
| **投稿者**（个人 / 部门） | 我写的东西怎么交上去、怎么被认可 | 四步向导 + 两种身份 + 贡献者主页（TA 的全部 Skill） |
| **使用者** | 怎么装到自己机器上 | 下载 ZIP / 一键复制命令 / 源码直链，三条路都通 |
| **维护者**（本站管理员） | 出问题怎么查 | 8 位 trace_id 贯穿日志与响应；操作审计流水 |

## 4. 需求清单（按优先级）

### 4.1 必须（P0）

| # | 需求 | 验收判据 |
| --- | --- | --- |
| R1 | 首页能看到"库有多大、有哪些分类" | 5 个统计数字非 0；15 个分类格子有计数 |
| R2 | 能按分类/场景/风险/身份/来源/状态筛选，并能叠加 | 筛选结果数与分类计数一致 |
| R3 | 能按关键词检索，且"名字命中的排最前" | 结果按分数降序；名称 100 / 标题 60 / 描述 40 / 标签 30 / 正文 10 |
| R4 | 详情页能看到完整 SKILL.md 与版本历史 | 正文非空；版本列表 ≥ 1 |
| R5 | 详情页能看到风险评估报告 | 6 个维度、四档等级、信号明细带 remediation |
| R6 | 能下载到可用的 Skill 包 | ZIP 可解压，内含 `<slug>/SKILL.md`；下载计数 +1 |
| R7 | 能编辑 Skill，且改动可回溯 | 编辑后版本数 +1 |
| R8 | 能删除但可恢复 | 归档后从默认列表消失，恢复后回来 |
| R9 | 能在线贡献并发布 | 四步全部走通；重复版本号被拒（409） |
| R10 | 有站点内在线文档 | ≥ 5 篇；术语有通俗解释 |

见 README 的「这个版本不做什么」。判据：**ESKH 里所有页面都不需要"等待远方返回"**。

## 5. 场景剧本

### 场景 A：找一份 pdf 处理手册

1. 打开首页 → 在分类格子里看到「开发与构建 50 个」→ 点进去
2. 左侧再加筛选「风险：安全」→ 剩 40 个
3. 顶部检索框输入 `pdf` → 第一个是 `pdf`（名称命中 100 分）
4. 详情页读 SKILL.md → 右栏看到风险 9 分「安全」→ 点「复制安装命令」
5. 终端粘贴，装到 `~/.claude/skills`

**全程无外部请求。** 断网也一样。

### 场景 B：部门把自己写的 Skill 交上来

1. 「在线贡献」→ 选身份「部门 / 企业」→ 填贡献者名「云原生部」
2. 填 Skill 名称 `k8s-manifest-review`、版本 `1.0.0`、源码直链（Gitee 地址）
3. 上传 `SKILL.md` → 系统立刻做预评估（风险分 + 信号）
4. 第 2 步填名字签协议 → 第 3 步提交 → 第 4 步「评估并发布」
5. 得到的 `skill_id` 是 `gitee:owner/repo/k8s-manifest-review`；同一版本再发一次会被拒

### 场景 C：安全同学想知道"这个 Skill 危险吗"

1. 「安全评估」页 → 粘贴 SKILL.md 正文 → 看到 85 分「高风险」
2. 展开信号：`SC2 远程下载并执行`（34 分，SKILL.md 第 12 行）
3. 按 `remediation` 让作者改成"下载 → 人工确认 → 再执行"
4. 重扫，分数降到 40「低风险」

## 6. 原型迭代记录（原型开发方法）

本版本按**原型开发**推进，每轮都是"能跑的最小闭环 → 用户反馈 → 扩展"：

| 轮次 | 范围 | 产出 | 反馈与调整 |
| --- | --- | --- | --- |
| P0 | 打通"库 → 详情 → 下载" | 1 张卡片 + 1 个详情 + 下载接口 | 卡片信息过载 → 描述压到 3 行、标签只留 2 个 |
| P1 | 加上筛选与检索 | 筛选器 + 加权检索 | 筛选条件放 URL 里，刷新不丢（当时是丢的） |
| P2 | 加上风险评估 | 报告页 + 试算框 | 用户看不懂"权重" → 每条信号加 remediation + 一句话结论 |
| P3 | 加上编辑与归档 | 编辑弹窗 + 软删 | 直接物理删除太危险 → 改成归档可恢复，硬删要 admin |
| P4 | 加上在线贡献 | 四步向导 | "签协议"和"提交"混在一起 → 拆成两步，签协议不推进状态 |
| P5 | 前端整体翻新 | 统一设计令牌 + 自研组件集 | 去掉 Element Plus：包体从 1.4 MB 降到 183 KB，风格可控 |

**原型阶段被砍掉的想法**（记在这里防止后人重犯）：
- 「Skill 评分/评论」：内网工具场景下没人写评论，且要引入用户体系 → 砍
- 「向量检索」：需要 embedding 服务或本地模型，违背"不联网"承诺 → 砍
- 「版本 diff」：实现成本高、使用频率低（有版本快照够用）→ 推迟

## 7. 与另两个版本的关系

```
ESKH（本版本）
  F = { 浏览, 检索, 详情, 编辑, 归档, 贡献四步, 分发三种, 静态风险 }
        ⊂ SSKH（+ Skill-MS 库语义 + 在线实测 + 统计口径质量评估）
        ⊂ PSKH（+ 多 Agent × 多 MCP 连通矩阵 + 多维实验 + 知识级分析）
```

**本版本必须保持极简**：一旦它开始出现"库语义"或"实测"，就说明分工错了。
