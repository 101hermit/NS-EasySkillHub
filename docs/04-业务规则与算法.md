# ESKH 04 · 业务规则与算法

本文写清"系统在什么条件下做什么"，全部可在代码里逐条对上。

## 1. 贡献状态机

```
                    ┌──────────────── reject（任何非 published 态）
                    ▼
   create ──► draft ──signCla──► draft(cla_signed=true) ──submit──► submitted ──publish──► published
                                                                                 │
                                                                                 └─ 重复版本 → 409，状态不变
```

规则（`ContributionService`）：

| # | 规则 | 违反时 |
| --- | --- | --- |
| 1 | 上传必须有 SKILL.md 正文（文件或文本） | 400 `MISSING_PARAM` |
| 2 | `contributor_name` 与 `name` 必填 | 400 `MISSING_PARAM` |
| 3 | `name` 归一化为 slug（小写 + 连字符） | 自动处理，不报错 |
| 4 | `signCla` 只置 `cla_signed/ signature / cla_signed_at`，**不推进状态** | — |
| 5 | `submit` 要求 `cla_signed = true` | 409 `STATE_ILLEGAL`（"还没签贡献者协议"） |
| 6 | `submit` 若已是 submitted/published → **幂等返回**，不报错 | — |
| 7 | `publish` 要求 `cla_signed = true` | 409 `STATE_ILLEGAL` |
| 8 | `publish` 若已 published → 幂等返回当前详情 | — |
| 9 | `publish` 若 rejected → 拒绝 | 409 `STATE_ILLEGAL`（"已被驳回，请重新提交"） |
| 10 | 目标 Skill 已存在且该版本号已存在 → 拒绝，**绝不覆盖** | 409 `VERSION_EXISTS` |
| 11 | `reject` 对 published 无效 | 409 `STATE_ILLEGAL` |
| 12 | 所有状态变化写 `op_log` | — |

## 2. skill_id 生成规则

```
1. 请求里给了 existing_skill_id      → 直接复用（给已有 Skill 追加版本）
2. source_url 能解析成三种平台之一     → <host>:<owner>/<repo>/<name>
      host ∈ { github, gitee, gitlab, gitcode }
      解析用正则：^https?://(github\.com|gitee\.com|gitlab\.com|gitcode\.com)/([^/]+)/([^/]+?)(\.git)?(/.*)?$
3. 否则                              → local:<slugify(贡献者名)>/<slugify(name)>
```

这条规则保证：**有源码直链的 Skill 能被追溯，纯上传的 Skill 也不会撞号**。

## 3. 风险评分算法（`RiskScanner`）

### 3.1 指标

32 条指标，每条有 `dimension`（6 维之一）、`severity`、`weight`（8–36）、`pattern`（正则）或 `structural`。

| 维度 | 指标数 | 看什么 |
| --- | ---: | --- |
| 提示注入 | 4 | 指令覆盖、隐藏指令、隐性指令、上下文填充 |
| 数据外泄 | 6 | 外发数据、读密钥环境变量、读凭据文件、访问 Agent/MCP 配置、枚举其它 Skill |
| 权限与代码执行 | 10 | sudo、子进程、shell、不安全参数/默认值、无约束工具、高风险自动决策、超范围能力、无上限消耗 |
| 供应链风险 | 5 | 未锁版本、远程下载执行、已知漏洞、恶意样本、攻击工具 |
| 系统提示与记忆 | 5 | 系统提示泄露、记忆投毒、输出未校验、输出拼进 SQL/命令、未声明权限 |
| 危险代码 | 2 | 运行时自我修改、持久化驻留 |

### 3.2 打分

```
score = min(100, Σ weight(命中的指标))
     每指标只计一次（不是每处命中都计）
     每指标最多记录 5 处命中；全部明细最多 40 条
level = score ≤20 safe | ≤50 low | ≤80 medium | else high
```

**为什么按"每条指标计一次"而不是"每处命中计一次"**：
一次 SKILL.md 里可能出现 20 处 `curl | bash`，但风险只增加一次；否则长度会主导分数。

**为什么用加权而不是计数**：1 条"远程下载执行"（34 分）比 4 条"依赖未锁版本"（8×4=32 分）更值得警惕。

### 3.3 结构性规则（唯一一条）

`LP3 · 未声明权限范围`（12 分）：`SKILL.md` 里既没有 `allowed-tools` 也没有
`permissions:` / `permission:` / `tools:`，即判为"没告诉读者会用到哪些能力"。

### 3.4 扫描输入

| 场景 | 输入 |
| --- | --- |
| 库导入 / 编辑 / 发布 | 只扫 `SKILL.md` 正文 |
| 贡献第 1 步（有 bundle） | `SKILL.md` + bundle 内文本（单文件 ≤ 256 KB，合计 ≤ 512 KB，只取文本扩展名） |
| 在线试算 | 用户粘贴的文本（文件名默认为 `SKILL.md`） |

bundle 抽取见 `BundleTextReader`：先判条目名（挡 `..`、绝对路径、含 `:`），再判扩展名，
再限大小 —— 三层都过了才读。

### 3.5 结论话术（`RiskService.conclusion`）

| 等级 | 一句话 |
| --- | --- |
| safe | 未发现高风险行为，可以直接使用。仍建议在使用前通读 SKILL.md。 |
| low | 发现少量可疑写法，通常是正常的工具调用。使用前建议确认它访问了哪些外部服务。 |
| medium | 存在需要人工确认的行为（读写文件、执行命令、访问网络）。建议在隔离环境先试跑。 |
| high | 存在高危行为特征（例如远程下载并执行、提权、读取凭据）。不建议在生产环境直接使用。 |

## 4. 关键词检索打分（`SkillService.search`）

```
候选集：SQL LIKE 粗筛（status=published，name/title/description/tags/content 任一命中），上限 200 条
打分：  名称 100 · 标题 60 · 描述 40 · 标签 30 · 正文 10（可叠加，故满分 240）
排序：  score 降序；同分按 SQL 的 download_count 降序（候选集的排序）
截断：  limit（默认 12，最大 50）
```

`matched_in` 字段返回命中的字段名（"名称 描述"），页面用于解释"为什么它排第一"。

**为什么不在 SQL 里算分**：权重需要可读、可测、可调；SQL 里算会让 H2 与 MySQL 出现行为差异。

## 5. 分页与排序

| 项 | 规则 |
| --- | --- |
| `page` | 从 1 开始；≤0 收敛为 1 |
| `size` | 默认 20；<1 收敛为 20；>100 收敛为 100（**不报错**，手改 URL 不该看到错误页） |
| `total_pages` | `(total + size - 1) / size` |
| 排序 | `sort` 走白名单；非白名单回落 `updated_at` |
| 稳定性 | 每种排序都追加第二键 `id DESC`，保证翻页不跳行 |

## 6. 归档（软删）与恢复

| 操作 | 前置 | 效果 |
| --- | --- | --- |
| `DELETE ?hard=false` | editor | `status = archived`，默认列表不含，可直接访问详情 |
| `DELETE ?hard=true` | **admin** | 删 `skill_file` + `skill`（`skill_version` / `risk_*` 保留作历史） |
| `POST /restore` | editor | `status = published` |

**为什么默认软删**：`skill_id` 是外部引用键（贡献记录、审计、用户收藏都指向它），
物理删除会留下悬空引用。

## 7. 分类计数的一致性

分类计数是**派生数据**（`category.skill_count`）。维护点只有两处：

1. `LibraryImportService.refreshCategoryCounts()` —— 导入结束时
2. `ContributionService.refreshCategoryCount()` —— 每次发布后

规则：遍历 15 个分类，各跑一次 `SELECT COUNT(*) FROM skill WHERE category_code = ?` 再 UPDATE。
代价可忽略（15 次索引计数），换来的是"分类格子的数字永远和筛选结果一致"。

## 8. ZIP 打包规则（`ZipPackageAdapter`）

```
归档结构：<slug>/SKILL.md
          <slug>/<该 Skill 目录下的其它文件...>
条目上限：5000
路径清洗：去掉空段 / "." / ".."；反斜杠转斜杠            ← zip-slip 防护
条目名清洗：去掉 \ / : * ? " < > |                      ← Windows 文件名兼容
主文件优先：SKILL.md 内容以"当前版本正文"为准（可能来自 skill_version，而非磁盘）
```

**为什么主文件不用磁盘上的**：下载 `?version=1.0.0` 时必须给那个版本的正文，
而不是磁盘上的最新版本。

## 9. 身份与权限矩阵

本版**不做登录**，身份来自请求头。这是内网工具的取舍，必须写清边界：

| 操作 | viewer | editor | admin |
| --- | :-: | :-: | :-: |
| 浏览 / 检索 / 详情 / 下载 | ✔ | ✔ | ✔ |
| 创建贡献 / 签协议 / 提交 / 发布 | ✔ | ✔ | ✔ |
| 编辑 Skill | ✘ 403 | ✔ | ✔ |
| 归档 / 恢复 | ✘ 403 | ✔ | ✔ |
| 物理删除 | ✘ 403 | ✘ 403 | ✔ |
| 查看操作审计 | ✔ | ✔ | ✔ |

**风险声明**：任何能打开页面的人都能把 `X-SKH-Role` 改成 `admin`。
因此**不要把它当作权限控制**，它只是"操作留痕 + 防手滑"。生产必须接 SSO。

## 10. 边界与不变量（写代码时的红线）

| # | 不变量 | 守护位置 |
| --- | --- | --- |
| I1 | 同一 `skill_id` 的同一 `version` 只存在一条 `skill_version` | DB `UNIQUE KEY uk_skill_version` + 业务层先查一次 |
| I2 | `skill.risk_score` / `risk_level` 与最近一次 `risk_audit` 一致 | 每次写 audit 后同事务回填 |
| I3 | `skill.content_sha256` 与 `content` 一致 | 只在写 content 的地方成对更新 |
| I4 | 分类计数之和 = `published + archived` 的 Skill 总数 | 两处 refresh 覆盖所有写入点 |
| I5 | 一个请求一个 trace_id | `TraceIdFilter` + `Trace.current()` |
| I6 | 列表接口永不返回 `content` | `CARD_COLS` 常量 + 自动化用例断言 |
| I7 | 下载的 ZIP 一定含 `<slug>/SKILL.md` | 打包前强制补主文件 |
